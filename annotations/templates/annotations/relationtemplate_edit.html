Node types
Open concept
Not the floor plan. This is the most common node type for appellations. The user can select an appellation with any interpretation (concept). You can optionally select a specific concept type; use this as a suggestion for the user as to the kind of concepts that should be used in that part of the relation.
Specific concept
In many nested relations it is desireable to specify ahead of time what the a node's interpretation should be. For example, if I am creating a template for a relation that expresses the idea of employment, I might include a node that is explicitly linked to the concept of "employee". When you select this option, start typing in the empty input that appears; this will trigger a concept search, and options should be displayed within a few moments.
Relation
Use this node type to indicate that the node in this relation part should be another relation. Enter the relation ID of the target relation.

About Relation Nodes: Relation nodes allow you to create more complex, nested relationships. When a node is of type "Relation", it creates a hierarchical structure where one relation becomes part of another. This is powerful for expressing complex ideas, such as "Person A believes that Person B influenced Person C" - where "Person B influenced Person C" is itself a relation that becomes the object of the "believes" relation.

Usage: When you select "Relation" as a node type, you'll need to specify which relation template part it refers to using the internal ID. This creates a connection between relation parts, allowing complex nested structures.

Relation Nodes

The relation nodes provides a way to create relations using a structured format:

Node
A node represents a concept in the relation template. Node values must also be included in the terminal nodes field. When you use Node type, you'll enter a reference to a specific node in the value field (like "0s", "1p", or "2o"), which corresponds to a node part and position in your template.
URI
A URI (Uniform Resource Identifier) represents a web resource. This typically points to an external concept or definition. When you use URI type, you can enter a full URI like "http://example.org/concept/person" that references an external resource directly.

You can use any combination of Nodes and URIs in your relation template when using relation nodes mode. The arrangement of these elements is flexible - you can have them in any order that makes sense for your relation.

How Relation Nodes Work:

  • The First Element represents the subject of the relation (who/what is doing the action)
  • The Second Element represents the predicate/relationship (the action or connection)
  • The Third Element represents the object (who/what is receiving the action)
For example, a relation representing "Person works at Organization" might use Node type for First and Third Elements (pointing to concept nodes like "0s" and "1o") and a URI type for the Second Element pointing to a "works_at" predicate URI.

Terminal Nodes and Expression:

  • Terminal nodes (e.g., "0s,1o,2p") identify specific nodes in your template that are referenced in the expression or relation nodes.
  • Expression (e.g., "{0s} is related to {1o} as {0s}") creates a human-readable sentence using references to those nodes.
  • These fields can now be defined independently - you have flexibility in how you structure your relations.
